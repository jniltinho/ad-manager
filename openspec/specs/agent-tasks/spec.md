# agent-tasks Specification

## Purpose
Token-protected file-server agent API with a persistent per-server task queue, queue monitor and audited tasks.

## Requirements

### Requirement: Agent API with token
The agent SHALL expose an HTTPS API in which every route except health requires `Authorization: Bearer <token>`. The token MUST be randomly generated by the binary itself, shown only once and stored only as a hash. Plain HTTP without TLS is accepted only on loopback with an explicit development option.

#### Scenario: Wrong token
- **WHEN** a call arrives without a token or with an invalid token
- **THEN** the agent responds 401 and enqueues nothing

### Requirement: Task queue
Changes on the file server SHALL go through a persistent queue (Redis) with a dedicated queue per server, limited retries and a result queryable by id.

#### Scenario: Server restarted mid-task
- **WHEN** the agent restarts with pending tasks
- **THEN** the tasks resume from the queue after it comes back

### Requirement: Queue monitor
The panel SHALL provide asynqmon at `/asynqmon`, with its original layout, reachable only with an administrator session; the agent MAY provide it protected by the token.

#### Scenario: Not logged in
- **WHEN** someone without a session opens `/asynqmon`
- **THEN** they get 401 and no queue data

### Requirement: Task audit
Every task enqueued by the panel SHALL produce an audit line with operator, server, task type, target and enqueue result.

#### Scenario: Audited share creation
- **WHEN** the operator creates a share
- **THEN** `audit.log` records `share.create` with the server and the name
